# Definition of Done

**Done = the entire USWDS 3.14.0 runs in OutSystems 11 Reactive Web, built exactly as it is.**

"Entire" and "exactly" are measured against USWDS's own published sources, not a hand-made list:

| What USWDS publishes | Count | Source |
|---|---:|---|
| Packages (foundations, components, utilities) | 75 | `packages/` in `@uswds/uswds` |
| Variants (every public Storybook story) | 208 | `*.stories.js` in the package |
| Behavior cases (USWDS's own JS test specs) | 414 | 64 `*.spec.js` files |
| Compiled CSS rules | 8,760 | official `uswds` bundle |

The lists are generated by `npm run inventory` into [`acceptance/inventory.md`](acceptance/inventory.md) and regenerated on every USWDS upgrade, so the target moves with USWDS rather than with our memory.

## The gates

USWDS 3.14.0 is done in O11 when **all seven gates pass**. Each gate is automated unless noted.

| # | Gate | Passes when | Status |
|---|---|---|---|
| 1 | **Every package assigned** | 75 / 75 packages owned by the Theme, a Block, or recorded as having no styles (`npm run build`) | ✅ Passing |
| 2 | **CSS identical** | 0 rules missing, 0 extra, 0 duplicated vs the official bundle (`npm run check`) | ✅ Passing |
| 3 | **Every variant built in O11** | Each of the 208 variants has a Style Guide screen built from O11 Blocks and platform widgets (no pasted USWDS HTML), using the same content as the USWDS story | ⬜ Phases 1–7 |
| 4 | **Looks identical** | Playwright screenshots of each O11 variant vs the USWDS reference rendering at 320, 480, 640, 1024 and 1400 px, with dynamic content (dates, generated IDs) masked. Threshold: ≤ 0.1% differing pixels, captured in the same environment | ⬜ Reference side ready |
| 5 | **Reads identically to assistive tech** | Playwright accessibility tree (roles, names, states, focus order) of each O11 variant equals the USWDS reference in `reference/aria/`. axe reports no violation the USWDS reference doesn't also have. Manual NVDA + VoiceOver pass per component (manual) | ⬜ Reference side ready |
| 6 | **Behaves identically** | All 414 USWDS behavior cases are accounted for: the 384 that describe something on a page are ported to Playwright and pass against the O11 Style Guide screens; the other 30 test USWDS internals (pure helper functions, JavaScript API calls, errors for malformed markup) and are recorded with a reason. This covers native rebuilds (accordion, modal, header, tooltip…) and Web Components alike | ⬜ Reference side ready |
| 7 | **Works as an O11 app** | All 9 USWDS page templates and 5 form patterns run as real screens from `USWDS_Templates`. A new app from `USWDS_AppTemplate` runs end to end with no OutSystems UI reference. Every interactive variant still works after client-side navigation away and back (50×), with no console errors or React warnings | ⬜ |

## What "exactly as is" allows

OutSystems forces a few differences in the HTML. They are allowed **only if gates 4–6 still pass**, meaning they change nothing a person sees, hears or does:

- IDs, `data-*` attributes and wrapper elements that OutSystems generates around widgets and Blocks.
- The modal stays where it is in the page instead of moving itself to the end of `<body>` (React requires this).
- Utility classes are `!important`, so they win even though OutSystems loads Block CSS after the Theme. USWDS supports this setting, and the visual result is the official one.
- Table sorting uses the platform's sort event, but must produce USWDS's sort buttons, `aria-sort` values and "now sorted by" announcement.

Any other difference is a defect.

## Out of scope for v1

- **20 Spanish variants.** English only for v1, as decided. Adding them later is a content change; the components are the same.
- **29 USWDS-internal test stories.** These are USWDS's own regression fixtures (`test/` folders), not part of the public design system.
- Additions beyond USWDS (extra list/detail/multi-step templates, the ban on the platform Switch and Icon widgets) are tracked in the plan but don't count toward done.
